# Памятка по работе с репозиторием GitHub

Эта инструкция поможет тебе начать работать с репозиторием проекта.
Если ты никогда раньше не работал с Git и GitHub — просто выполняй шаги по порядку.

Репозиторий используется для хранения кода и совместной работы над программой.

---

# 1. Что нужно установить

Перед началом работы нужно установить систему контроля версий **Git**.

Скачать Git можно здесь:
https://git-scm.com/downloads

После установки открой терминал и проверь:

```
git --version
```

Если выводится версия Git — всё установлено правильно.

---

# 2. Настройка Git (делается один раз)

Открой терминал и выполни команды:

```
git config --global user.name "Твоё Имя"
git config --global user.email "твой_email"
```

Пример:

```
git config --global user.name "Ivan Ivanov"
git config --global user.email "ivan@mail.com"
```

Это нужно, чтобы Git понимал, кто делает изменения в проекте.

Проверить настройки можно так:

```
git config --list
```

---

# 3. Принятие приглашения в репозиторий

Ты получишь приглашение на GitHub.

1. Открой GitHub.
2. Перейди в уведомления.
3. Нажми **Accept invitation**.

После этого у тебя появится доступ к репозиторию.

---

# 4. Клонирование репозитория на компьютер

Теперь нужно скачать репозиторий на компьютер.

Открой терминал и выполни:

```
git clone https://github.com/vl1ko/notes-app-student-project.git
```

После этого появится папка проекта.

Перейди в неё:

```
cd notes-app-student-project
```

Теперь ты работаешь с локальной копией проекта.

---

# 5. Основной принцип работы

Работа с проектом происходит по следующей схеме:

1. Создать новую ветку
2. Сделать изменения в коде
3. Сохранить изменения (commit)
4. Отправить ветку на GitHub (push)
5. Создать Pull Request

Ветка **main** защищена.
Напрямую в неё изменения вносить нельзя.

---

# 6. Создание рабочей ветки

Перед началом работы всегда создавай новую ветку.

```
git checkout -b feature-name
```

Примеры:

```
git checkout -b feature-notes-editor
git checkout -b feature-save-notes
git checkout -b fix-memory-bug
```

---

# 7. Добавление изменений

После того как ты изменил код, нужно добавить изменения в Git.

Посмотреть изменения:

```
git status
```

Добавить файлы:

```
git add .
```

Или конкретный файл:

```
git add filename.cpp
```

---

# 8. Создание коммита

Коммит — это сохранение изменений.

```
git commit -m "Краткое описание изменений"
```

Примеры:

```
git commit -m "Added note creation feature"
git commit -m "Fixed crash when saving notes"
git commit -m "Implemented notes storage"
```

Коммит должен кратко описывать, что было сделано.

---

# 9. Отправка изменений на GitHub

После коммита нужно отправить изменения на сервер.

```
git push origin имя_ветки
```

Пример:

```
git push origin feature-notes-editor
```

После этого ветка появится на GitHub.

---

# 10. Создание Pull Request

После отправки ветки нужно создать Pull Request.

1. Открой репозиторий на GitHub
2. GitHub предложит **Create Pull Request**
3. Нажми кнопку
4. Добавь описание изменений
5. Отправь Pull Request

После этого руководитель проверит код и примет изменения.

---

# 11. Обновление проекта

Перед началом новой работы нужно обновить проект.

```
git checkout main
git pull origin main
```

Затем создать новую ветку.

---

# 12. Полезные команды

Показать состояние проекта:

```
git status
```

Показать историю коммитов:

```
git log
```

Показать все ветки:

```
git branch
```

Переключиться на ветку:

```
git checkout branch-name
```

---

# 13. Правила работы с репозиторием

1. Никогда не работай напрямую в ветке **main**
2. Каждую задачу выполняй в отдельной ветке
3. Делай понятные сообщения коммитов
4. Перед началом работы обновляй main
5. Все изменения отправляй через Pull Request
